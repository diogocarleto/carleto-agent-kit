## UI Registers

Pick the register before visual design or critique. A good interface can fail by using the wrong register.

### Product or tool

Use for SaaS, dashboards, admin surfaces, editors, operational systems, and repeated workflows.

- Prioritize scanning, comparison, predictable navigation, dense but organized content, and fast repeated action.
- Use restrained styling, clear state, practical empty/error/loading handling, and stable layouts.
- Avoid oversized heroes, decorative card-heavy sections, stock-like imagery, and marketing copy inside the product surface.

### Brand or marketing

Use for landing pages, product pages, portfolios, campaigns, venues, and object-focused pages.

- Make the brand, product, place, person, or offer obvious in the first viewport.
- Use real or generated imagery when visual inspection matters.
- Keep the hero connected to the next section; avoid a first viewport that feels like a detached poster.
- Put value props in supporting copy. Do not make the headline carry every explanation.

### Content or editorial

Use for articles, documentation, catalogs, journals, media libraries, education, and discovery surfaces.

- Prioritize readability, rhythm, media treatment, metadata, wayfinding, and saved/continued state.
- Keep line length, typography, headings, captions, and related content intentional.

### Game or immersive

Use for games, playgrounds, simulations, 3D scenes, and interactive demos.

- Prioritize responsive interaction, animation clarity, feedback loops, input latency, and nonblank rendering.
- Verify canvases/scenes with screenshots or pixel checks when available.

### Native app

Use for iOS, Android, and mobile-first app screens.

- Prefer platform conventions over web metaphors.
- Respect safe areas, navigation idioms, touch reach, font scaling, gestures, system colors, and accessibility services.
